# Replay protocol v1 (experimental)

`hydirctl replay init <linked-elf>` emits a JSON `InputSpec v1` bound to the exact ELF SHA-256. Edit its input bytes and goal, then run `hydirctl replay verify <linked-elf> <input.json>`. On Linux with Bubblewrap installed, `hydirctl replay <linked-elf> <input.json>` attempts one fresh execution and emits `NativeReplayReport v1`.

On other hosts, `replay` emits an `unsupported_host` report with no observed exit or output.

The current contract accepts little-endian linked x86-64 ELF, raw hex-encoded `argv_hex` (excluding argv0), `stdin_hex`, and relative input `files`. `origins` name byte ranges within those channels with raw, ASCII, or UTF-8 encoding and optional allowed-byte alphabets. Ranges and alphabets are checked against the supplied bytes. An output goal combines its present predicates with AND: exit code, stdout substring, and stderr substring. The default goal created by `init` is exit code zero. Limits are 32 arguments, 16 files, 256 origins, 1 MiB combined input, 30 seconds, 1 GiB address space, and 1 MiB captured output. The JSON parser rejects unknown fields and oversized input.

The Linux runner stages the exact ELF and files into a read-only work tree, clears the environment, creates private user, PID, network, IPC, and UTS namespaces, and applies address-space, CPU, core-file, and file-size limits. It requires Bubblewrap and fails closed when it cannot confirm child startup and exit through Bubblewrap's separate JSON status FD. A timeout, output limit, setup failure, or unsupported host never becomes `goal_matched`. Native output is an observation for one input under this environment; it is not an equivalence proof. Bubblewrap shares the host kernel, so use an isolated machine for hostile binaries.

On Ubuntu 24.04, AppArmor's unprivileged user-namespace policy can deny Bubblewrap's private-network setup with `loopback: Failed RTM_NEWADDR: Operation not permitted`. Install and load Ubuntu's `bwrap-userns-restrict` profile before running replay or capture; the Linux CI gate does this and probes the isolated network namespace. Do not remove `--unshare-net` to make execution pass, because the runner's no-network behavior is part of its contract.

`NativeReplayReport v1` records the binary and canonical input digests, runner, status, exit value, hex output, elapsed time, and diagnostics. `validate_replay_report` checks its binding, bounds, and whether an asserted goal result agrees with the recorded output. Bubblewrap reports signal termination as a shell-style exit value. Values at least 128 remain `runner_error` with an ambiguity diagnostic and no exact exit or signal claim. Input files are read-only and process-created output files are not collected.

This is an M4 foundation. Bounded captured-state Triton execution exists for pure validators; general process resumption, file output capture, cancellation, and Windows WSL launch remain open. The [Ubuntu 24.04 semantic gate](https://github.com/Achxy/hydir-2/actions/runs/35892246939) passed fresh replay with argv, stdin, and files, as well as mismatch and crash cases. `doctor` probes whether Bubblewrap can create the required private user and network namespaces on the current Linux host.

## ExecutionSnapshot v1 contract

`ExecutionSnapshot v1` binds the exact ELF and canonical `InputSpec`, records a stop point with optional ELF virtual address and load bias, one thread's register observations, process mappings, and at most 32 selected 4096-byte pages. Each register or page is explicitly present or unavailable. Pages absent from the artifact are also unavailable: `read_snapshot_memory` returns a missing-page error and never substitutes zero bytes. `hydirctl snapshot verify <elf> <input.json> <snapshot.json>` checks bounds, digest bindings, mapping/page consistency, RIP versus stop PC, and the one-thread claim.

On Linux, `hydirctl capture <linked-elf> <input.json> --function <symbol> --output <snapshot.json>` experimentally stops at the entry of a simple named C function. `--address <elf-vaddr>` instead accepts a file-backed executable ELF virtual address, including in a stripped PIE. The address path uses GDB `starti` to stop before normal execution, resolves the staged ELF load bias from process mappings, and continues to the relocated target. Both paths run inside Bubblewrap and capture x86-64 general registers, flags, process mappings, and up to eight selected code, stack, and argument pages through bounded GDB/MI. GDB starts with init files and auto-loading disabled. The command records timeout, missing pages, multi-threaded execution, and runner failures explicitly. On Windows it emits `unsupported_host`.

Capture argv remains limited to ASCII letters, digits, `_`, `-`, `.`, and `/`; replay accepts the broader raw-byte argv contract. Paths whose first component starts `.hydir-` are reserved for runner staging. A stop at a function entry or address does not by itself establish a mapping from parsed state back to original input bytes. The Ubuntu 24.04 gate passed named-symbol capture and a stripped-PIE stop inside a validator after `fgets`; it checked that the captured argument bytes equal the declared stdin origin. This is a test oracle, not an automatic provenance claim. `doctor` reports the bounded capture capability when its local Bubblewrap and GDB prerequisites are present. Automatic post-input origin mapping, complete TLS state, demand memory reads, general process resumption, and richer process events remain open.

## OriginProbe v1

`hydirctl snapshot probe-origin <elf> <input.json> <snapshot.json> <origin-id> --register <name> [--output <probe.json>]` compares the declared input-origin bytes with the memory pointed to by an analyst-selected captured register. The versioned report binds the binary, input, and exact snapshot digests. It records the chosen location, runtime address, observed bytes when available, and a `matched`, `different`, or `unavailable` result. `hydirctl snapshot verify-origin <elf> <input.json> <snapshot.json> <probe.json>` recomputes and checks the report. Missing pages and unavailable registers remain unavailable; they never become a mismatch or a match. The evidence scope is always `byte_equality_only`: equality does not establish that those memory bytes came from the declared input channel. A solver using this mapping must record the analyst assumption, and only fresh native replay can validate a proposed original input.

## SnapshotResumePlan v1 and experimental return solve

For a stopped snapshot and matched origin probe, build a bounded Triton handoff:

```bash
hydirctl snapshot plan-return program.elf input.json snapshot.json probe.json --code-bytes 64 --return 1 --output plan.json
hydirctl snapshot verify-plan program.elf input.json snapshot.json probe.json plan.json
hydirctl solve snapshot-return program.elf input.json snapshot.json probe.json plan.json --candidate-output candidate.json --slice-output slice.json --claim-output claim.json --recipe-output recipe.json --output solve.json
hydirctl recipe verify program.elf recipe.json
hydirctl recipe replay program.elf recipe.json
```

`--code-bytes` is an analyst-selected extent starting at the captured RIP. The plan requires exact captured code bytes within one executable mapping, all 16 general-purpose registers plus RIP and EFLAGS, at most eight present pages, and an origin of 1–32 bytes. It binds the canonical snapshot and probe hashes to the ELF/input hashes. The bridge rejects uncaptured memory/register reads, writes to uncaptured or non-writable pages, self-modifying code in the selected extent, calls, syscalls, and control flow outside that extent. Raw and ASCII input origins are supported; UTF-8-specific symbolic constraints are not yet supported.

The experimental solver runs a bounded concrete seed, queries the return-value condition, flips observed branches for additional seeds, and re-executes a candidate in Triton before returning a `function_witness`. The current plan fixes limits of 16 seeds, 1,024 instructions per seed, 32 solver queries, 1 second per query, and 20 seconds overall. Its status distinguishes unsupported effects, solver uncertainty, and search-budget exhaustion; none means global unreachability. The CLI replaces only the declared origin bytes in a new `InputSpec` and attempts fresh native replay. It labels the candidate `native_validated_candidate` only when the original ELF meets the declared `InputSpec` goal. On Windows, the replay status remains `unsupported_host` and the claim remains `function_witness`.

When the original seed reaches a return that misses the requested value, the bridge includes `input_condition_slice` in `solve.json` and can export the same `InputConditionSlice v1` with `--slice-output`. It binds the ELF, input, snapshot, probe, captured code hash, and origin. The slice lists executed instruction occurrences, observed branch and return decisions, origin-byte offsets that occur structurally in each decision's Triton AST, and the instruction occurrences behind those expressions. Its scope is one captured seed trace. Structural occurrence can overapproximate causal relevance, and the report explicitly records that the origin mapping is only a byte-equality assumption; memory-address dependencies, other paths, and environment effects are not analyzed. `ast_walk_complete` states only whether the bounded AST traversal finished. If the failing seed does not complete, no slice is emitted. The CLI checks the slice's identity, bounds, and internal references before writing it; the slice is evidence for investigation, not a minimal input proof or a replacement for original-ELF replay.

When a failing-seed slice, function witness, mismatched replay of the original input, and matched replay of the candidate are all available, `solve snapshot-return` can also export `InvestigationClaim v1` and `AnalysisRecipe v1`. The claim states that one original-ELF replay missed the declared goal and one candidate replay met it. It records the changed bytes, failed decision occurrence, relevant structural input offsets, unresolved dependencies, assumptions, and the hashes that invalidate it. The recipe embeds both inputs, the snapshot, probe, resume plan, Triton result and slice, both recorded replays, and the claim; it references the ELF by SHA-256 rather than embedding executable bytes. Recipe JSON is bounded to 24 MiB and contains captured memory pages and input bytes, so inspect it before sharing. `recipe verify` checks all artifact bindings and exact candidate-byte replacement without executing the program. Its success means recorded artifacts are internally consistent. `recipe replay` performs fresh native runs of both inputs and reports whether the before-and-after claim reproduces on the current host. Each replay is one observation under that environment; the contrast does not prove global reachability or byte-level causality. Recipe export is unavailable without a completed failing-seed slice and both native replay outcomes.

The Python bridge's pure-function and missing-state tests run locally where Triton is installed. The Ubuntu 24.04 gate passed a post-input capture → Triton function witness → fresh original-ELF replay, including candidate byte `0x41` from an initial `0x42`. `doctor` reports this experimental bounded capability when the local Bubblewrap, GDB, and Triton prerequisites are present. The gate establishes one pure-validator workflow; it does not establish automatic input provenance, general external-effect handling, or success on unfamiliar challenges.
